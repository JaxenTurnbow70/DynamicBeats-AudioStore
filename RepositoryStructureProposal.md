# DynamicBeats - Repository Structure Proposal

This is a starting point for discussing how we want the DynamicBeats repository to work. Nothing here is final.

The goal is to start simple and let the structure develop as we use it.

## 1. Shared Music

The core of the repository is a shared collection of practice music.

We can experiment with organizing tracks by genre, BPM, energy, contributor, or whatever makes sense to us.

For now, the priority is simply having **one shared place to find the music we're practicing.**

## 2. Basic Metadata

We want to keep basic information about each track consistent between DJs and different DJ software.

Things like:

* Artist
* Title
* BPM
* Key
* Length
* DJ software used to analyze the track

The goal isn't to build a complicated database yet.

If a track is analyzed in Rekordbox, Serato, Traktor, etc., we can record the useful basic information in a simple format that everyone can understand.

Over time, we can decide what additional information is actually worth tracking.

## 3. Organization & Voting

We can use GitHub's **Issues, Discussions, and reactions** to propose changes to the library.

For example:

> "Should this track move into the DnB practice collection?"

People can discuss it and vote with reactions before someone makes the change.

This gives us a lightweight way to **collectively curate the library** without needing a complicated system.

## 4. Mix Challenges

We can create challenges that give us a reason to practice with the shared library.

Examples:

* Mix two tracks that shouldn't work together.
* Create a 5-minute progression from three tracks.
* Make a transition using only loops.
* Rework someone else's mix.
* Find the most unexpected transition between two genres.

The challenge can simply record who participated, what they made, and what they learned.

## 5. Collaborations

The repository can also hold collaborative projects.

One DJ might start a mix, another adds to it, and another changes the direction.

We can keep the different versions and eventually build collaborative sets together.

This turns the repository into a place where we're **making things together**, rather than just exchanging music.
